# 目前設備可先做的操作流程

## 適用條件

目前你手上的設備是：

- MCU 板
- 訊號產生器
- 示波器

在還沒有完整 DUT / 大電流 power path 的情況下，現在最值得先完成的是這個縮小版里程碑：

- MCU 正確接收並計數訊號產生器的 `SYNC`
- PC 可透過 `USB Type-C` 與 MCU 通訊
- PC 可透過網路用 SCPI 控制示波器

這三件事打通之後，後面的完整系統整合會輕鬆很多。

## 硬體接法

### MCU 與 PC

- MCU 用 `Type-C` 接到 PC
- 確認 Windows 已出現對應的 `COM Port`

目前已驗證可用：

- `COM20`

### 訊號產生器到 MCU

把訊號產生器的 `SYNC OUT` 接到 MCU 的 `FG_PULSE_MON_IN`。

目前預設腳位在：

- [board_config.c](C:/Users/winston_YEH/Documents/25230/CODE/艾科/firmware/Core/Src/board_config.c:26)

目前定義是：

- `PB12`

如果你實際 PCB 接的不是這個腳位，就改這裡。

### 示波器

把示波器接上與 PC 同網段的 LAN，確認可以用 IP 連線。

目前 host 預設值是：

- `192.168.0.100:5025`

如果你的示波器 IP 不同，CLI 或 GUI 裡改掉即可。

## 先確認 MCU 通訊正常

先用 CLI 測試 MCU：

```powershell
python -m host.src.pulse_host.cli --port COM20 ping
python -m host.src.pulse_host.cli --port COM20 status
python -m host.src.pulse_host.cli --port COM20 get-sync-count
```

正常情況下會看到類似：

```text
OK
STATUS IDLE COUNT=0 SYNC=1
SYNC_COUNT 1
```

## 驗證 SYNC 計數

### 建議做法

1. 先把訊號產生器輸出設成低頻方波，方便觀察
2. 打開 `SYNC OUT`
3. MCU 接好 `SYNC OUT`
4. 先重置計數
5. 再讀一次 `SYNC_COUNT`

對應指令：

```powershell
python -m host.src.pulse_host.cli --port COM20 reset-sync-count
python -m host.src.pulse_host.cli --port COM20 get-sync-count
python -m host.src.pulse_host.cli --port COM20 monitor --interval 0.5
```

你應該會看到：

- `SYNC_COUNT` 持續增加

這代表：

- 外部脈波有進 MCU
- `EXTI15_10` 中斷正常
- MCU 計數路徑正常
- USB 通訊回傳正常

## 驗證示波器 SCPI 控制

現在已經補了 CLI 版的示波器控制，不一定要開 GUI。

先測試能不能辨識示波器：

```powershell
python -m host.src.pulse_host.cli scope-identify --scope-host 192.168.0.100
```

如果回傳 `Keysight ... DSO-X 4024G ...` 之類字串，代表 SCPI 通道正常。

接著可以做基本控制：

```powershell
python -m host.src.pulse_host.cli scope-stop --scope-host 192.168.0.100
python -m host.src.pulse_host.cli scope-clear --scope-host 192.168.0.100
python -m host.src.pulse_host.cli scope-autoscale --scope-host 192.168.0.100
python -m host.src.pulse_host.cli scope-preset-trigger --scope-host 192.168.0.100
python -m host.src.pulse_host.cli scope-single --scope-host 192.168.0.100
```

其中 `scope-preset-trigger` 目前做的是：

- 開啟 `CH1~CH4`
- trigger source 設為 `CHAN4`
- trigger level 設為 `1.0V`
- timebase 設為 `2 ms/div`

如果你的 SYNC 或 trigger marker 實際接在別的通道，之後可以再調整這個 preset。

## 最小可用流程

如果你現在要用最短流程確認整條 bench path 是通的，照下面做就好：

1. MCU 用 Type-C 接 PC，確認 `COM` 埠出現
2. FG `SYNC OUT` 接到 MCU `PB12`
3. 示波器接 LAN，取得 IP
4. CLI 驗證 MCU
5. CLI 驗證 scope SCPI
6. `reset-sync-count`
7. 讓 FG 開始輸出
8. `monitor` 看 `SYNC_COUNT` 是否增加
9. 用 `scope-single` 或 `scope-run` 看示波器是否能正常抓到波形

## 現在先不要做的事

在只有這些設備時，先不要把重點放在：

- 高能量 DUT pulse stress
- 快速保護邏輯完整驗證
- precharge / discharge 的真實高壓母線流程
- OCP / thermal / timeout 的真硬體 fault 鏈

這些都需要更多硬體條件。

## 沒有接完整 pulse / 訊號源時怎麼操作

如果你現在只有：

- MCU
- 示波器
- 或只有外部 `SYNC`

但還沒有把真正的 pulse source / DUT 流程接好，請先用這種模式操作：

1. `連接 MCU`
2. `PING`
3. `更新狀態`
4. `Start Monitor`
5. 觀察：
   - `STATUS`
   - `FAULT`
   - `SYNC_COUNT`
6. `連接示波器`
7. `Identify`
8. 用：
   - `Run`
   - `Stop`
   - `Autoscale`
   - `立即截圖`

這個階段先不要把重點放在：

- `Pulse 首尾截圖`
- `START COUNT=n` 之後一定要抓到第一個 pulse

因為這套流程會要求：

- MCU 真的進入 pulse run
- 示波器真的等到你要的 trigger
- 流程最後真的結束

如果目前只是示波器有看到某個邊緣，或 `SYNC_COUNT` 在增加，但 MCU 其實仍停在 `STATUS IDLE`、`COUNT 0`，那 `Pulse 首尾截圖` 很容易最後 timeout。

## 示波器 Timing 怎麼調

現在 GUI 已經可以調這些示波器 trigger / timing 參數：

- `Trigger Source`
- `Trigger Level`
- `Trigger Sweep`：`AUTO / NORMAL`
- `Timebase (s/div)`

位置在：

- `示波器` 分頁
- 展開 `進階示波器控制`

建議先這樣做：

1. 選你探棒實際接的 `Trigger Source`
2. 設 `Trigger Level`
3. 選 `Trigger Sweep`
4. 設 `Timebase (s/div)`
5. 按 `套用 Trigger`
6. 再按：
   - `Trigger Preset`
   - 或 `Preset + Single`

如果現在還在 bench bring-up、觸發源不穩，建議先從這組開始：

- `Trigger Sweep = AUTO`
- `Timebase = 0.002`

如果脈波比較短，再往下調：

- `0.0005`
- `0.0002`
- `0.0001`

## 下一步建議

等你把這一階段跑順後，下一步最值得做的是：

1. 確認 `SYNC_COUNT` 和訊號產生器設定頻率一致
2. 把示波器 trigger channel 與實際接線對齊
3. 決定是否要把 `scope-preset-trigger` 變成更貼近你 bench 的專用 preset
4. 再往 `ARM / START / reduced pulse flow` 的縮小版驗證前進
## 自動 Pulse 結束後截圖

現在 GUI 已經支援一鍵完成這條流程：

1. 先在 `MCU` 分頁確認 MCU 已連線，`PING` / `STATUS` 正常
2. 在 `示波器` 分頁確認示波器已連線，`Identify` 正常
3. 回到 `MCU` 分頁右下 `輪詢與紀錄`
4. 設定：
   - `Pulse Count`
   - `截圖 Timeout (s)`
   - `截圖檔案`
5. 按 `Pulse 結束後截圖`

GUI 會自動做：

1. 對示波器送 `Trigger Preset`
2. 對示波器送 `Single`
3. 對 MCU 送 `START COUNT=n`
4. 輪詢 `STATUS / FAULT / COUNT / SYNC_COUNT`
5. 判定 pulse 完成
6. 從示波器抓一張 PNG
7. 儲存到你指定的路徑

### 截圖會存到哪裡

- 如果你有填 `截圖檔案`
  - 就存到你填的完整路徑
- 如果你沒填
  - 會自動存到 repo 根目錄下的 `captures/`
  - 檔名格式類似：
    - `pulse_100_20260417_153000.png`

### 怎麼看截圖

有兩種方式：

1. 在 GUI 按 `開啟截圖`
   - 如果 `截圖檔案` 指到現有檔案，會直接開圖
   - 如果還沒有檔案，會開啟 `captures/` 資料夾

2. 直接到資料夾打開
   - 預設資料夾：
     - [captures](C:/Users/winston_YEH/Documents/25230/CODE/艾科/captures:1)

### 建議操作順序

1. `連接 MCU`
2. `PING`
3. `連接示波器`
4. `Identify`
5. 視需要先按一次 `Preset + Single`
6. 設好 `Pulse Count`
7. 設好 `截圖檔案` 或直接用預設
8. 按 `Pulse 結束後截圖`
9. 完成後按 `開啟截圖`

### 注意事項

- 這個流程會假設：
  - MCU 已經可以接受 `START COUNT=n`
  - 示波器 trigger 已設定在你要看的通道
- 如果目前沒有完整 pulse source / DUT，或 MCU 根本沒有進入 `RUNNING`
  - 先不要用 `Pulse 首尾截圖`
  - 改用 `立即截圖`、`Run / Stop / Autoscale`、`Start Monitor`
- 如果中途進入 `FAULT`
  - GUI 會停止流程並跳錯誤
- 如果超過 `截圖 Timeout`
  - GUI 會跳 timeout，這時先檢查：
    - `Pulse Count` 是否合理
    - MCU 是否真的有進入 `RUNNING`
    - FG / SYNC 接線是否正常
